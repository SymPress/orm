# Release 0.3.1

Generated schema migrations refresh the database schema and recompute forward SQL
and destructive-policy checks during execution. Factory creation retains only
the intended CREATE-schema hash and stable `orm-schema:<manager>` identity.
Live database changes do not change that identity. Generated rollback remains
irreversible and requires a separately reviewed inverse migration.

The optional migration integration now requires SymPress Migration 1.0.4 or later,
whose WordPress executor resolves SQL plans under the advisory lock. Composer
rejects older installed migration packages. Custom executors need the deferred
operation contract to provide the same planning boundary.

Local PHP 8.5 verification passed: `composer qa` (57 tests, 208 assertions) and
`composer tests:database` (5 tests, 51 assertions) against a fresh disposable
MariaDB schema. The database regression changes a column after generation and
before lock acquisition, checking explicit destructive intent, safe refusal,
preserved rows and stable identity. Hosted release verification and registry
publication are separate delivery steps.
